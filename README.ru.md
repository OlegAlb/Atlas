# Atlas

[![CI](https://github.com/OlegAlb/Atlas/actions/workflows/ci.yml/badge.svg)](https://github.com/OlegAlb/Atlas/actions/workflows/ci.yml)

[English](README.md) · **Русский**

Компактный движок знаний с RAG: принимает документы компании, режет их на чанки,
индексирует через BM25 и эмбеддинги, ищет гибридным пайплайном, переранжирует
кандидатов и отвечает на вопросы с помощью LLM.

Наибольшую ценность представляет не вызов LLM, а слой поиска и обвязка для его оценки.

> **Статус: экспериментальный проект, не поддерживается.**
> Разработка остановлена в августе 2026. Рынок RAG-баз знаний оказался
> переполнен заметно более сильными продуктами, и ниши, где это было бы
> рентабельно, я не нашёл. Код публикуется как референсная реализация поискового
> пайплайна и его бенчмарка, а не как продукт.

## Что реализовано

- **Загрузка** — исходный документ → загрузчик → парсер → `KnowledgeDocument` → чанкер → индексатор
- **Чанкинг** — рекурсивный сплиттер с иерархией разделителей, подсчётом размера в токенах (tiktoken) и перекрытием
- **Поиск** — BM25 (в памяти), плотный поиск (косинус по эмбеддингам), гибридный с фьюзингом RRF
- **Реранкинг** — абстракция провайдера с `noop`, `reverse` и реранкером Jina
- **Провайдеры** — LLM (Groq), эмбеддинги (Jina), реранкинг (Jina), каждый за интерфейсом
- **API** — Fastify: `GET /health`, `POST/GET /knowledge/documents`, `POST /chat`
- **Оценка** — recall@k, MRR, nDCG на двух размеченных датасетах, плюс оценка загрузки документов

## Архитектура

```
Documents
    │
    ▼
DocumentLoader → DocumentParser → KnowledgeDocument
    │
    ▼
RecursiveChunker → KnowledgeChunk[]
    │
    ├──► BM25Indexer      (in-memory inverted index)
    └──► EmbeddingIndexer (Jina / noop, cached)
    │
    ▼
SearchPipeline
    query expansion → retriever (bm25 | dense | hybrid+RRF) → reranker
    │
    ▼
ChatUseCase → LLM (Groq)
```

Слои идут в одном направлении: `api → application → domain`, а инфраструктура и
провайдеры подставляются через `apps/core/src/bootstrap/createContainer.ts`.
Без магии фреймворка и декораторов — только конструкторы.

## Быстрый старт

Работает без единого API-ключа: эмбеддинги и реранкинг по умолчанию используют
детерминированные `noop`-провайдеры, поэтому загрузка документов, поиск и весь
бенчмарк считаются локально и бесплатно.

```bash
npm install
cp .env.example .env      # опционально, дефолты работают без ключей

npm run dev               # http://localhost:3000
curl http://localhost:3000/health
```

Загрузить документ и найти его:

```bash
curl -X POST http://localhost:3000/knowledge/documents \
  -H "Content-Type: application/json" \
  -d '{"title":"Оплата заказа","content":"Оплатить заказ можно картой, через СБП или наличными при получении."}'

curl http://localhost:3000/knowledge/documents
```

`POST /chat` дополнительно требует ключ LLM (`LLM_API_KEY` в `.env`) — у
провайдера LLM нет режима `noop`.

### Реальные провайдеры

Задаются в `.env`:

| Провайдер  | Модель                          | Переменные                                      |
| ---------- | ------------------------------- | ----------------------------------------------- |
| Эмбеддинги | `jina-embeddings-v5-text-small` | `EMBEDDING_PROVIDER=jina` + `EMBEDDING_API_KEY` |
| Реранкинг  | `jina-reranker-v3`              | `RERANKING_PROVIDER=jina` + `RERANKING_API_KEY` |
| LLM        | `openai/gpt-oss-120b` (Groq)    | `LLM_API_KEY`                                   |

## Оценка качества

Метрики при **k = 5**. Данные бенчмарка NFCorpus в репозитории не хранятся —
скачайте их один раз в игнорируемый git файл:

```bash
npm run fetch:data    # скачивает тестовый сплит NFCorpus, ~6 МБ, проверяет разметку

npm run eval          # загрузка + поиск на noop-провайдерах, ключи не нужны
npm run eval:bm25     # только BM25
npm run eval:jina     # с реранкером Jina (нужен RERANKING_API_KEY)
```

Без `fetch:data` датасет `regression` продолжает работать; данные нужны только
для `hard`, и раннер прямо об этом сообщает.

### `regression` — 30 статей поддержки (на русском), 51 запрос с ручной разметкой

| Поиск        | Реранкер         | Recall@5 | MRR   | nDCG@5 |
| ------------ | ---------------- | -------- | ----- | ------ |
| BM25         | noop             | 0.510    | 0.438 | 0.457  |
| dense        | noop             | 0.941    | 0.840 | 0.866  |
| hybrid (RRF) | noop             | 0.941    | 0.656 | 0.727  |
| BM25         | jina-reranker-v3 | 0.510    | 0.454 | 0.468  |
| hybrid (RRF) | jina-reranker-v3 | 0.961    | 0.824 | 0.859  |
| dense        | jina-reranker-v3 | 0.941    | 0.830 | 0.859  |

### `hard` — тестовый сплит NFCorpus, 3 633 абстракта, 323 размеченных запроса

| Поиск | Реранкер | Recall@5 | MRR   | nDCG@5 |
| ----- | -------- | -------- | ----- | ------ |
| BM25  | noop     | 0.554    | 0.475 | 0.271  |

Что говорят цифры:

- BM25 в одиночку слаб на русском: нет стемминга и языковой токенизации, работает
  только точное совпадение форм. Плотный поиск почти вдвое поднимает recall.
- Гибрид с RRF поднимает recall, но **портит MRR** (0.656 против 0.840 у одного
  dense): фьюзинг двух ранжирований без реранкера вытаскивает слабые попадания
  BM25 наверх.
- Кросс-энкодер это лечит — гибрид идёт с 0.656 до 0.824 по MRR — но стоит
  одного сетевого запроса на каждый вопрос.
- На NFCorpus nDCG@5 = 0.271 попадает в ожидаемый диапазон для простого BM25:
  опубликованный baseline даёт nDCG@10 ≈ 0.325.

## Тесты

```bash
npm test
```

38 юнит-тестов, около секунды, без сети и без API-ключей:

- **метрики** — nDCG / recall@k / MRR на пустой выдаче, `k` больше длины списка,
  недостижимых релевантных документах, кейсах без разметки
- **чанкер** — сохранность слов, исходные границы документа, последовательный
  порядок и реальный контракт перекрытия между соседними чанками
- **BM25** — document frequency и средняя длина после инкрементальных обновлений,
  направление скоринга и то, что перестройка действительно сбрасывает индекс
- **реранкер** — пустой список кандидатов не должен доходить до провайдера
  (реальное падение: API отвечал 422 на пустой массив `documents`)
- **оценщик** — должен считать каждый кейс, а не только первый

## Известные ограничения

- Хранение в памяти: после перезапуска документы, чанки и индексы теряются
- Поддерживаются только доументы в формате TXT;
- Нет авторизации, rate limiting и маппинга ошибок валидации в 400
